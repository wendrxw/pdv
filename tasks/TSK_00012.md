# Adaptação do backend ao novo frontend

1. **Leitura compulsória:** `agents.md`.
2. **Verificação do tenant:** Antes de qualquer `Model.objects.get()`, confirmar se existe filtro por `tenant`.
3. **Django Admin:** Todo novo model deve ser registrado no admin com list_display e filters.
4. **Commit:** Usar Conventional Commits.

Desenvolva o backend completo, robusto, seguro e escalável para um sistema de **PDV (Ponto de Venda) brasileiro**, seguindo exatamente a estrutura e os requisitos funcionais das interfaces já definidas.

O backend deve ser preparado para atender as seguintes áreas:

* Venda / PDV
* Produtos
* Categorias
* Clientes
* Estoque
* Caixa
* Financeiro
* Relatórios
* Operadores/usuários
* Formas de pagamento
* NFC-e
* Configurações

O sistema deve utilizar arquitetura profissional, modular, REST API, banco de dados relacional e regras de negócio centralizadas no backend.

---

# 1. Stack recomendada

Utilize:

* **Node.js**
* **TypeScript**
* **NestJS**
* **PostgreSQL**
* **Prisma ORM**
* **JWT para autenticação**
* **bcrypt/argon2 para hash de senha**
* **class-validator/class-transformer**
* **Swagger/OpenAPI**
* **Docker**
* **Redis**, quando necessário para cache, sessões, locks ou operações de alta frequência.

Estruture o projeto seguindo princípios de:

* Clean Architecture
* SOLID
* Domain-driven organization
* Separation of concerns
* Repository pattern quando fizer sentido
* Services/use cases para regras de negócio
* DTOs para entrada e saída
* Guards e policies para autorização

O backend deve ser preparado para futuramente suportar múltiplos caixas e múltiplos estabelecimentos.

# 22. Regras críticas de consistência

Operações financeiras e de estoque devem utilizar transações de banco de dados.

Ao finalizar uma venda:

```text
1. Validar usuário
2. Validar caixa aberto
3. Validar produtos
4. Validar estoque
5. Criar venda
6. Criar itens
7. Calcular subtotal
8. Aplicar descontos
9. Validar pagamentos
10. Registrar pagamentos
11. Baixar estoque
12. Criar movimentações de estoque
13. Criar movimentações de caixa
14. Atualizar venda para COMPLETED
15. Criar registro de auditoria
```

Tudo deve ocorrer dentro de uma transação quando possível.

Se qualquer etapa crítica falhar, não deixar o sistema em estado parcialmente concluído.

---

# 23. Concorrência

O sistema deve considerar dois caixas vendendo o mesmo produto simultaneamente.

Evitar estoque negativo por condições de corrida.

Utilizar:

* transações
* row locking quando necessário
* validação de estoque dentro da transação

Exemplo:

Se existem 2 unidades e dois caixas tentam vender 2 unidades simultaneamente, apenas uma operação deve conseguir concluir.
