# TSK_00007 — PDV: Vendas e Caixa

Fonte: `docs/context-pdv.md` §15 (PDV/Venda), §16 (Caixa), §24 (UX);
`docs/general.md` §48 (integração financeiro←venda).

## Objetivo

Fluxo principal do caixa: abrir caixa → vender (carrinho) → pagar →
finalizar, com integração transacional a EstoqueService e módulo
financeiro. Tela do PDV rápida, teclado-first (leitor de código de
barras = campo com Enter).

## App

`apps/sales`

## Models

| Model | Campos-chave |
|---|---|
| Caixa | uuid, tenant, operador FK User, status (ABERTO/FECHADO), saldo_inicial, saldo_final_esperado, saldo_final_informado, diferenca (property), data_abertura, data_fechamento, observacao_fechamento |
| MovimentacaoCaixa | caixa, tipo (SUPRIMENTO/SANGRIA), valor, motivo, usuario |
| Venda | uuid, tenant, numero (sequencial por tenant), caixa FK, operador, cliente_nome (livre; FK futura), status (ABERTA/FINALIZADA/CANCELADA), subtotal, desconto, total, observacao, data_abertura, data_finalizacao |
| ItemVenda | venda, produto FK, quantidade Decimal(12,3), preco_unitario congelado no momento da venda, subtotal; unique venda+produto |
| PagamentoVenda | venda, forma_pagamento FK financial.FormaPagamento, valor, valor_bruto/taxa/valor_liquido preparados |

Índices tenant+status, tenant+numero; numero sequencial por tenant via
lock na abertura de venda.

## Regras

- Só existe venda com caixa ABERTO do operador/tenant.
- Itens consomem estoque **no ato** via `EstoqueService.registrar_venda`
  (transacional); cancelamento de item/venda devolve via
  `registrar_devolucao`.
- Preço unitário congelado do Produto.preco_venda no momento; backend é
  autoridade — frontend envia produto+quantidade, nunca totais.
- Desconto validado no backend (0 ≤ desconto ≤ subtotal).
- Finalização transacional: exige ≥1 pagamento somando exatamente o
  total; gera `MovimentacaoFinanceira` ENTRADA na conta do caixa para
  pagamentos à vista; forma FIADO/CREDIARIO (codigo OUTRO + flag?) →
  gera `ContaReceber` com parcelas via ReceivableService.
  - Decisão: `FormaPagamento.gera_conta_receber` BooleanField default
    False — formas marcadas geram recebível em vez de entrada imediata.
- Cancelamento de venda finalizada: devolve estoque, estorna
  movimentações financeiras (ESTORNO_ENTRADA) e cancela conta a receber
  pendente. Nunca apaga registros.
- Fechamento de caixa: esperado = saldo_inicial + suprimentos +
  entradas − sangrias (calculado das movimentações); diferenca =
  informado − esperado; grava histórico.

## Services (`apps/sales/services.py`)

- `SalesError`
- CaixaService: `abrir_caixa(tenant, operador, saldo_inicial)` (bloqueia
  se já há ABERTO por tenant? não — multi-caixa permitido; bloqueia
  segundo ABERTO do mesmo operador), `suprimento`, `sangria`,
  `fechar_caixa(caixa, saldo_informado)`
- VendaService: `abrir_venda(caixa)`, `adicionar_item(venda, produto,
  quantidade)` (merge se item existir), `remover_item`,
  `aplicar_desconto`, `adicionar_pagamento`, `finalizar_venda`
  @atomic, `cancelar_venda` @atomic

## Views/URLs

- `/app/pdv/` — tela do operador: seleção/caixas abertos, abre caixa;
  `/app/pdv/venda/<uuid>/` tela de venda (busca por código/nome com
  fetch JSON, carrinho server-side renderizado, POSTs rápidos:
  add/remover/desconto/pagamento/finalizar/cancelar)
- `/app/pdv/api/produto-busca/?q=` JSON (nome/SKU/código)
- `/app/vendas/` histórico com filtros · `/app/vendas/<uuid>/` detalhe ·
  `cancelar/` POST
- `/app/caixa/` lista/histórico · `/app/caixa/<uuid>/` detalhe com
  conferência
