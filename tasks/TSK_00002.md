## Procedimento padrão do agente (aplicar a todas as tasks)

1. **Leitura compulsória:** `agents.md`.
2. **Verificação do tenant:** Antes de qualquer `Model.objects.get()`, confirmar se existe filtro por `tenant`.
3. **Django Admin:** Todo novo model deve ser registrado no admin com list_display e filters.
4. **Commit:** Usar Conventional Commits.


## Tarefa

Implementar a Fase 2 (Produtos) do módulo de Produtos, Estoque e Inventário
(`docs/general.md`, seções 5–13, 27–28, 34, 36–37):

- Models `Categoria`, `Marca` e `Produto` isolados por tenant
  (`TenantAwareModel`), com UUID gerado no backend e datas automáticas.
- Produto: nome, descricao, tamanho, sku (único por tenant), unidade de
  medida (choices compatíveis com fiscal), categoria/marca do mesmo tenant,
  preco_custo/preco_venda (`DecimalField(12,2)`, >= 0), estoque_minimo,
  estoque_maximo, ativo (soft delete), observacao.
- Constraints de unicidade por tenant (SKU; nome de categoria).
- `ProductService` com regras de negócio (criar, alterar, desativar);
  views apenas orquestram.
- Django Admin para os três models com list_display/filters/search.
- Interface em Django Templates + Tailwind: `/produtos/` (listagem com
  busca por nome/SKU, filtros por categoria/marca/status, paginação),
  `/produtos/novo/`, `/produtos/<uuid>/`, `/produtos/<uuid>/editar/`.
- Validações no backend (preços não negativos, categoria/marca do tenant).
- Testes: multi-tenancy (isolamento total), criação/edição/desativação,
  UUID automático, validações.

Fora do escopo: código de barras (TSK_00003), estoque (TSK_00004),
inventário (TSK_00005), campos fiscais (módulo fiscal futuro — estrutura
separada, não poluir o model principal).
