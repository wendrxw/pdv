## Procedimento padrão do agente (aplicar a todas as tasks)

1. **Leitura compulsória:** `agents.md`.
2. **Verificação do tenant:** Antes de qualquer `Model.objects.get()`, confirmar se existe filtro por `tenant`.
3. **Django Admin:** Todo novo model deve ser registrado no admin com list_display e filters.
4. **Commit:** Usar Conventional Commits.


## Tarefa

Implementar a Fase 3 (Barcode) do módulo de Produtos, Estoque e Inventário
(`docs/general.md`, seções 7–9, 30–31):

- `BarcodeService` com `generate()`, `validate()` e
  `calculate_check_digit()` para EAN-13 interno (uso interno da loja/PDV,
  não GTIN oficial).
- Código de barras: 13 dígitos, dígito verificador correto, único dentro
  do tenant (constraint), indexado, não reutilizado após exclusão lógica.
- Geração sempre no backend; nunca confiar em JavaScript para o código
  definitivo.
- `BarcodeRenderer` gerando SVG dinamicamente (imagem não armazenada no
  banco; código numérico é a fonte da verdade).
- Integração no cadastro de produto: campo codigo_barras opcional com
  botão "Gerar código" e aceitação de código manual validado; busca de
  produto pelo código na listagem (compatível com leitor USB HID).
- Testes: geração, dígito verificador, unicidade por tenant, validação,
  renderização SVG, localização por código.

Fora do escopo: impressão física (futura), leitura por câmera (futura),
integração PDV (futura).
